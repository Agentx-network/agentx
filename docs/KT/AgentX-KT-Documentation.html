1. Executive summary

AgentX is a lightweight, self-hosted AI agent runtime written in Go, plus a cross-platform desktop GUI. It lets a user run a personal AI agent that can chat, use tools (shell, file I/O, web search, image generation), learn hot-loadable "skills", schedule tasks/reminders, talk over messaging channels (Telegram, Discord, etc.), and manage a BNB Smart Chain (BSC) crypto wallet.

It is the client-side / runtime half of the broader AgentX Network product (a "decentralized AI agent economy"). This repository — internally nicknamed "OpenClaw" — contains the Go agent engine, the CLI, the background gateway service, and the Wails-based desktop application. The marketing site, the LaunchPad, and on-chain/economy pieces live in other repositories (see §12).

One-line mental model: A single Go binary (agentx) that runs an LLM tool-calling loop. It can run as a CLI, as a long-lived background gateway service, or be driven by a desktop app. All state lives in ~/.agentx/.

Key point: The desktop app is a thin client. It does not run the agent itself — it sends messages to the gateway over HTTP (POST /api/chat, Server-Sent-Events streaming). The gateway hosts the actual agent loop, tools, memory, and channels. This separation matters for deployment (see §7 and §13).

4. The three runtimes (one binary)

The same agentx binary behaves differently depending on how it is invoked:

RuntimeHow it startsRole
CLIagentx <command>One-off commands: wallet ops, skill install, cron, onboarding, status. Also how you chat in a terminal.
Gatewayagentx gateway (run as a background service)Long-lived process. Serves the HTTP API on 127.0.0.1:18790, runs the agent loop, connects messaging channels, executes scheduled crons/heartbeats. This is the "backend" the desktop chat talks to.
Desktopagentx-desktop (separate Wails binary)Native GUI. Auto-starts the gateway if not running, then drives it over HTTP.

6. Core concepts

6.1 The agent loop (pkg/agent)

The heart of the system. For each user message:

  1. Build context (context.go): system prompt (identity, rules, workspace info) + bootstrap files + installed skills summary + memory + session history/summary.
  2. Call the model via the Fantasy SDK (fantasy_runner.go is the primary path; runLLMIteration is a legacy path). The model streams text and may emit tool calls.
  3. Execute tools and feed results back; loop until the model produces a final answer or hits the iteration cap.
  4. Persist the user + assistant messages, then maybe summarize (see 6.4).

fantasy_runner.go also contains resilience logic for weak models: recovering text-form tool calls, auto-running web search when the model "narrates" instead of acting, and (added this handover) auto-searching skills and attaching uploaded files.

6.2 Providers & models (pkg/providers)

Model selection is config-driven. The default is Auto (best available), which resolves to openrouter/auto — OpenRouter's router that picks a model per request. Provider protocol (anthropic/openai/gemini/openrouter/…) is chosen in fantasy_bridge.go. Capability maps (imagecapability.go, visioncapability.go) declare which models can generate images or accept image/audio input.

6.3 Tools (pkg/tools)

ToolWhat it does
execRun a shell command (e.g. ffmpeg, git). Powerful — the main way the agent "does" things.
read_file / write_file / list_dirSandboxed file I/O within the workspace (+ uploads dir).
web_search / web_fetchSearch the web / fetch a URL (Brave/Tavily/etc. per config).
image_generate / configure_image_providerCreate images (Gemini/OpenAI/Replicate/Seedance); manage the image provider + key.
find_skills / install_skillSearch ClawHub and install a skill into the workspace.
cronSchedule reminders / recurring tasks.
spawn / subagentRun background sub-agents for long tasks.
i2c / spiTalk to hardware on edge devices.

6.4 Sessions & memory (pkg/session)

Every conversation is a "session", keyed by channel+peer (the desktop chat resolves to agent:main:main). Two on-disk representations, kept separate on purpose:

FilePurposeTrimmed?
sessions/<key>.jsonAgent context — what the model sees. Has messages[] + a text summary.Yes — when a chat exceeds ~20 messages or ~75% of the context window, older messages are summarized into summary and dropped (summarize.go → TruncateHistory).
sessions/<key>.transcript.jsonlUI display history — append-only, one JSON message per line. (Added this handover.)No — never summarized. The desktop reads this so the chat window keeps full history even after the context is compacted.
Why two files? The model must stay within a token budget (so context is summarized), but a user expects their chat history to persist. The transcript decouples "what the agent remembers" from "what the UI shows." Before this, restarting the app made summarized-away messages disappear from the UI.

6.5 Skills (pkg/skills)

Skills are folders containing a SKILL.md (plus optional scripts) that teach the agent a capability. They live in ~/.agentx/workspace/skills/. The agent can find_skills (search ClawHub) and install_skill (download+extract). A built-in wallet skill is auto-installed. Skill summaries are injected into the system prompt so the agent knows what it has.

6.6 Channels (pkg/channels)

Adapters that connect the agent to messaging platforms. Each channel receives messages, routes them (pkg/routing) to a session, runs the agent loop, and streams the reply back. Enabled/configured per-channel in config.json. Telegram is the one currently enabled in this environment.

7.2 The gateway lifecycle (important)

The desktop app auto-starts the gateway on launch if it isn't already reachable (main.go → DashboardService.StartGateway). It locates the binary with exec.LookPath("agentx"), which finds whatever agentx is first on PATH (normally /usr/local/bin/agentx), and installs/refreshes the systemd unit to point there. The Dashboard has RESTART / STOP buttons that drive the same service.

7.3 Manual gateway control (Linux)

systemctl --user status  agentx-gateway.service
systemctl --user restart agentx-gateway.service
systemctl --user stop    agentx-gateway.service
tail -f ~/.agentx/gateway.log        # runtime logs

8. Build & run locally

8.1 Prerequisites

Go 1.26+, Node.js + npm (for the desktop frontend), the Wails CLI (go install github.com/wailsapp/wails/v2/cmd/wails@latest), and on Linux the WebKit2GTK dev libs.

8.2 Build commands (Makefile)

# CLI + gateway binary  → build/agentx-linux-amd64
make build

# Desktop app  → cmd/agentx-desktop/build/bin/agentx-desktop
make desktop-build       # (wails build -tags webkit2_41)

# Desktop hot-reload dev mode
make desktop-dev

# Run the whole test suite
make test        # or: go test ./...

8.3 The redeploy loop (what you do after a backend change)

Critical: Chat/schedulers/wallet all run in the gateway, not the desktop app. Rebuilding only the desktop app will not pick up backend changes. You must rebuild the agentx binary, replace the one the service runs, and restart the gateway.
make build
systemctl --user stop agentx-gateway.service
cp build/agentx-linux-amd64 ~/.local/bin/agentx      # or /usr/local/bin (needs sudo)
systemctl --user start agentx-gateway.service
# then, for UI changes:
make desktop-build && ./cmd/agentx-desktop/build/bin/agentx-desktop

8.4 Launching the desktop app from a terminal (Linux gotcha)

If you launch from a shell running inside a snap (e.g. the VS Code snap terminal), the snap injects library paths that crash the WebKit window (undefined symbol: __libc_pthread_init). Launch with a clean environment instead:

env -i HOME=$HOME USER=$USER \
  PATH=/home/$USER/.local/bin:/usr/local/bin:/usr/bin:/bin \
  DISPLAY=:0 XAUTHORITY=/run/user/$(id -u)/gdm/Xauthority \
  DBUS_SESSION_BUS_ADDRESS=unix:path=/run/user/$(id -u)/bus \
  XDG_RUNTIME_DIR=/run/user/$(id -u) \
  ./cmd/agentx-desktop/build/bin/agentx-desktop

9. Config & workspace (data on disk)

9.1 ~/.agentx/config.json

The master config: providers & API keys, the model list, agent defaults (model, max tokens, temperature, max tool iterations, workspace path), channel settings, image providers, gateway host/port, and tool toggles. Edited via the desktop Config page or by hand. The default agent model is Auto (best available) = openrouter/auto.

11. Work done during this handover

All on branch fix/bug-fixes. Confirm commit status with git status — some or all may still be uncommitted at handover.

11.1 Skill discovery fixes

  • Proactive skill offer: when the model says it "can't do X", the runner auto-runs find_skills and offers to install a matching skill instead of dead-ending (fantasy_runner.go shouldAutoSkillSearch; prompt rule in context.go).
  • Search recall: the ClawHub search is prefix-matching, so "video compression" returned ~1 result but "video compress" returned ~9. Added query broadening (stopword-strip + stemming) in pkg/skills/query_expand.go, used by both the chat tool and the Config search.
  • UI: clearing the Config search box now clears stale results.

11.2 Chat file upload (new feature)

  • New pkg/attach package: classify (image/audio/doc/video), validate (type sniff, size caps, count/total limits), store into workspace/uploads/, and confine paths (security).
  • Files flow through the existing bus.InboundMessage.Media []string (paths) contract. Documents → read_file; images/audio → sent to the model as Fantasy FileParts (true vision/audio); video → path surfaced so the agent runs ffmpeg via exec (e.g. compression).
  • New pkg/providers/visioncapability.go gates image/audio by model capability; if the model can't see/hear, it accepts + warns rather than failing.
  • Desktop: paperclip picker (PickAttachments), attachment chips/thumbnails, inline render, and a marker block so attachments survive reload.

11.3 Full chat transcript (new)

  • SessionManager.AppendTranscript writes an append-only *.transcript.jsonl; the desktop GetChatHistory prefers it (falling back to the summarized .json). Fixes chat history vanishing after restart once a conversation was summarized.

13. Known issues, gotchas & watch-outs

GotchaDetail / mitigation
Backend changes need the gateway restartedRebuilding the desktop app alone does nothing for chat/tools/memory. Rebuild the agentx binary and restart agentx-gateway.service (see §8.3).
Gateway binary "reverts"The desktop app rewrites the service unit to exec.LookPath("agentx") = /usr/local/bin/agentx on launch. If you deploy a new build to ~/.local/bin but /usr/local/bin is on PATH, the desktop can point the service back at the old binary. Clean fix: install the new build to /usr/local/bin/agentx (sudo).
openrouter/auto creditsThe configured OpenRouter key was out of credits (HTTP 402 in gateway.log). Chat/vision can fail intermittently. Fund the key or set a concrete model (e.g. a Gemini/GPT-4o key) in Config.
Model is "Auto"Vision/audio capability can't be known ahead of time; the code optimistically attaches media for the auto router and warns for known text-only models.
Snap-shell launch crashLaunch the desktop app with a sanitized env -i … (see §8.4) when starting from a snap terminal.
Old chat history not recoverableThe transcript feature records from its introduction onward; conversations summarized before it existed can't be restored.
Commit hygieneProject preference: do not add "Generated with / Co-Authored-By" AI attribution to commits or PRs.

16. Onboarding checklist for the next engineer

  1. Install Go 1.26+, Node, the Wails CLI, and WebKit2GTK dev libs.
  2. Clone github.com/Agentx-network/agentx; check out fix/bug-fixes (or main).
  3. make build and make test — confirm a green build.
  4. Run ./build/agentx-linux-amd64 onboard (or use the desktop Installer page) to create ~/.agentx/config.json and set a provider API key.
  5. make desktop-build, launch the desktop app (§8.4), and send a chat message — confirm the gateway auto-starts and streams a reply.
  6. Read, in order: pkg/agent/loop.go → fantasy_runner.go → context.go → cmd/agentx/internal/gateway/helpers.go. That is the whole request path.
  7. Internalise §13 (gotchas) — especially the gateway-restart and binary-reversion issues.
  8. Skim §11 for the most recent changes and where they live.
